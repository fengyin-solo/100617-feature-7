# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 掘进环次（交接班定位）

- 列表入口：`/ring`（班组记录员）；`/ring/shared` 是对全项目共享的只读视图，同一份取数、只给只读。
- 查询：环号区间、掘进班组、环次进度叠加；可按环号/起始里程/掘进速度升降序；条件与页码全部
  写在 URL query 里，翻页、跳详情再返回都不丢。空结果逐项回查，指出是哪一项对不上号
  （环号区间/班组/进度）。
- 详情：`/ring/detail/:id`，重点看刀盘扭矩与出土方量，附掘进速度修改审计。
- 唯一事实源：`ring` 台账。轴线超限复核清单（阈值：水平/垂直偏差绝对值 > 50mm）由
  `axisReviewList()` 实时派生，环次页与轴线页读到的超限条数必然一致；进度节点的实际掘进量由
  `progressLedger()` 按节点环号区间实时重算，不另存一份；运营概览的环次条数同样跟着台账变。
- 速度统计口径：只统计台账「掘进速度」可解析为正数的环（待掘进无速度不参与平均）；老数据
  贯通过程记录里的速度仅在 v2 迁移时回填一次（见 `src/data/migrate.ts`），统计阶段不再读。
- 权限与幂等：只有本掘进班组记录员能改本班组环次的掘进速度与状态，跨班组提交、共享只读提交
  一律在服务层退回；重复提交相同值只落一条审计；非法输入原样退回不入库。
- 存量环次迁移按掘进日期顺序补录环号、里程、日期、速度、班组，schema 版本存在
  `shield-tunnel-construction:meta`，每版本只跑一次。
- 自检：`cd frontend && npm run selftest`（区间/排序/分页/诊断/鉴权/幂等/派生一致/迁移共 55 项断言）。
